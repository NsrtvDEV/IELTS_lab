# Техническое задание: IELTS Lab

Платформа для подготовки к IELTS Academic: прохождение mock-тестов в формате реального экзамена — целиком или по одной секции, автоматическая проверка Listening и Reading, проверка Writing и Speaking преподавателем или AI, подсчёт band score и отслеживание прогресса.

## 1. Общие сведения

| | |
|---|---|
| Название | IELTS Lab |
| Тип | Веб-приложение: REST API (backend) + клиент (frontend, отдельно) |
| Формат экзамена | Только IELTS Academic (General Training не поддерживается) |
| Тип тестов | Mock-тесты из четырёх секций: Listening, Reading, Writing, Speaking. Проходятся целиком или по одной секции |
| Язык интерфейса | Русский / английский (контент тестов — на английском) |

### 1.1. Цели

1. Дать ученику пройти mock-тест целиком или любую его секцию отдельно в условиях, близких к реальному: таймер, формат заданий.
2. Сразу показывать результат Listening и Reading по официальной шкале перевода баллов в band.
3. Оценивать Writing и Speaking по четырём официальным критериям с текстовым отзывом.
4. Показывать прогресс ученика по каждой секции.

### 1.2. Роли

| Роль | Возможности |
|---|---|
| Ученик (`student`) | Регистрация, профиль, прохождение тестов, просмотр результатов и прогресса |
| Преподаватель (`teacher`) | Всё, что у ученика, плюс проверка Writing и Speaking, создание и редактирование тестов |
| Администратор (`admin`) | Всё, что у преподавателя, плюс управление пользователями и ролями, публикация тестов, шкалы перевода баллов |

## 2. Функциональные требования

### 2.1. Регистрация и авторизация

- Регистрация по email и паролю. Email уникален, пароль не короче 8 символов.
- Пароль хранится только в виде хеша (argon2).
- Вход выдаёт пару токенов:
  - access token (JWT), срок жизни 15 минут;
  - refresh token, срок жизни 30 дней. В базе хранится только его хеш (`refresh_tokens.token_hash`).
- Обновление токенов с ротацией: старый refresh token помечается `revoked`, выдаётся новый. Повторное использование отозванного токена отзывает все токены пользователя.
- Выход отзывает текущий refresh token.
- Заблокированный пользователь (`is_active = false`) не может войти, его токены не принимаются.

### 2.2. Профиль ученика

- Поля: имя и фамилия (обязательны при регистрации), родной язык, часовой пояс.

### 2.3. Каталог тестов

- Каждый тест — mock-тест IELTS Academic из четырёх секций.
- Из карточки теста ученик выбирает: пройти весь тест или одну секцию (Listening, Reading, Writing или Speaking).
- Ученик видит только опубликованные тесты (`is_published = true`).
- В карточке теста видно, какие секции ученик уже прошёл.

### 2.4. Структура теста

Тест состоит из четырёх обязательных секций в фиксированном порядке:

| Секция | Время | Содержимое |
|---|---|---|
| Listening | 30 мин (+10 мин на перенос ответов в бумажном формате, на платформе не нужно) | 4 части (Part 1–4), у каждой своё аудио, всего 40 вопросов |
| Reading | 60 мин | 3 текста, всего 40 вопросов |
| Writing | 60 мин | Task 1 (150+ слов, ~20 мин) и Task 2 (250+ слов, ~40 мин) |
| Speaking | 11–14 мин | Part 1 (интервью), Part 2 (карточка: 1 мин подготовки, до 2 мин ответа), Part 3 (дискуссия) |

Вопросы Listening и Reading объединены в группы с общей инструкцией, например «Questions 1–5. Write NO MORE THAN TWO WORDS AND/OR A NUMBER». Нумерация вопросов сквозная внутри секции (1–40).

Поддерживаемые типы вопросов:

| Тип | Как отвечает ученик |
|---|---|
| Multiple choice (один ответ) | Выбор одного варианта |
| Multiple choice (несколько ответов, «Choose TWO») | Выбор нескольких вариантов |
| True / False / Not Given, Yes / No / Not Given | Выбор одного из трёх |
| Matching headings / information / features / sentence endings | Выбор варианта из общего списка группы |
| Sentence / summary / note / form / table / flow-chart completion, gap fill | Ввод текста |
| Short answer | Ввод текста |
| Diagram labelling, map / plan labelling | Ввод текста или выбор буквы |

### 2.5. Прохождение теста

1. Ученик начинает попытку: создаётся `test_attempt` со статусом `in_progress`. Режим задаётся полем `section_type`:
   - пусто — полный экзамен, все четыре секции подряд в порядке Listening → Reading → Writing → Speaking;
   - указана секция — проходится только она.
2. Для каждой проходимой секции создаётся `section_attempt`. Время начала фиксирует сервер.
3. Таймер секции контролирует сервер. После истечения времени (плюс 30 секунд запаса на сеть) ответы не принимаются, секция закрывается автоматически.
4. Ответы автосохраняются при каждом изменении. Ученик может вернуться к попытке после обрыва связи, если время секции не истекло.
5. Listening: аудио воспроизводится только один раз, перемотка запрещена.
6. Writing: счётчик слов отображается во время ввода. Ответ короче минимума принимается, но преподаватель видит предупреждение.
7. Speaking: ответы записываются через микрофон браузера и загружаются в файловое хранилище. Для Part 2 отдельно отсчитывается минута подготовки.
8. Ученик может прервать попытку: статус `abandoned`, результат не учитывается в прогрессе.

### 2.6. Проверка Listening и Reading

- Проверка автоматическая, сразу после закрытия секции.
- Текстовый ответ нормализуется перед сравнением: обрезаются пробелы, регистр не учитывается, несколько пробелов подряд заменяются одним.
- Ответ засчитывается, если совпадает с любым из допустимых вариантов (`correct_answers.answer_text`), например «colour» и «color».
- Ответ длиннее лимита слов группы (`word_limit`) не засчитывается.
- В вопросах с выбором ответ засчитывается, если выбран ровно тот набор вариантов, что указан в правильных ответах.
- Сумма баллов (`raw_score`, 0–40) переводится в band по таблице `band_conversion` (шкалы Academic для Listening и Reading).

### 2.7. Проверка Writing и Speaking

- После сдачи этих секций попытка переходит в статус `pending_review`.
- Проверяет преподаватель или AI (`grader_type`). Оценка AI помечается в интерфейсе как предварительная. Если есть оценка преподавателя, в результате используется она.
- Writing, отдельно для каждого задания, целые баллы 0–9 по критериям:
  - Task Achievement (Task 1) / Task Response (Task 2);
  - Coherence and Cohesion;
  - Lexical Resource;
  - Grammatical Range and Accuracy.
- Speaking, целые баллы 0–9 по критериям:
  - Fluency and Coherence;
  - Lexical Resource;
  - Grammatical Range and Accuracy;
  - Pronunciation.
- К каждой оценке прилагается текстовый отзыв.
- Преподаватель видит очередь работ на проверку, отсортированную по времени сдачи.

### 2.8. Подсчёт band score

- Band по критериям Writing-задания: среднее четырёх критериев.
- Band за Writing: Task 2 весит вдвое больше Task 1, `(T1 + 2 × T2) / 3`.
- Band за Speaking: среднее четырёх критериев.
- Общий балл (`overall_band`): среднее четырёх секций. Считается только для полного экзамена; у попытки по одной секции результат — band этой секции.
- Округление до ближайших 0.5 по правилам IELTS: дробная часть `.25` округляется до `.5`, а `.75` — до следующего целого. Например, 6.25 → 6.5, 6.75 → 7.0, 6.1 → 6.0.
- Попытка получает статус `finished`, когда оценены все её секции: для полного экзамена — четыре, для попытки по секции — одна.

### 2.9. Результаты и прогресс

- Страница результата попытки: band по каждой секции и общий балл, разбор ответов Listening и Reading (ответ ученика, правильный ответ, ссылка на место в тексте), оценки и отзывы по Writing и Speaking.
- Страница прогресса: график band по каждой секции во времени (учитываются и полные экзамены, и попытки по секциям), график overall band по полным экзаменам, самые частые ошибки по типам вопросов.

### 2.10. Управление контентом

Доступно преподавателю и администратору.

- Создание теста: секции, тексты и аудио, группы вопросов, вопросы, варианты ответов, правильные ответы, задания Writing и Speaking.
- Загрузка файлов (аудио, изображения графиков и карт) в S3-совместимое хранилище (MinIO). В базе хранится только ссылка.
- Предпросмотр теста в том виде, в котором его увидит ученик.
- Публикует тест только администратор. Перед публикацией проверяется полнота теста: есть все четыре секции, 40 вопросов в Listening и Reading, у каждого вопроса есть правильный ответ, у Writing есть оба задания, у Speaking есть все три части.
- Опубликованный тест, по которому уже есть попытки, нельзя удалить, только снять с публикации.

### 2.11. Администрирование

- Список пользователей с поиском по email, смена роли, блокировка.
- Редактирование шкал `band_conversion` (Listening и Reading).

## 3. Модель данных

Модели — в [app/models.py](app/models.py), миграции — в [alembic/versions/](alembic/versions/).

| Область | Таблицы |
|---|---|
| Пользователи | `users`, `user_profiles`, `refresh_tokens` |
| Контент тестов | `tests`, `sections`, `passages`, `question_groups`, `questions`, `question_options`, `correct_answers`, `writing_tasks`, `speaking_tasks` |
| Попытки и ответы | `test_attempts`, `section_attempts`, `user_answers`, `user_answer_options`, `writing_responses`, `speaking_responses` |
| Оценки | `writing_assessments`, `speaking_assessments`, `band_conversion` |

Основные правила целостности задаются в базе:

- band: от 0 до 9 с шагом 0.5; оценки по критериям: целые от 0 до 9; `raw_score`: от 0 до 40;
- одна секция каждого типа в тесте, один ответ на вопрос в попытке;
- вариант ответа принадлежит либо вопросу, либо группе вопросов;
- удалить вопрос или задание, на которые уже есть ответы учеников, нельзя (`ON DELETE RESTRICT`).

## 4. API

REST, JSON, префикс `/api/v1`. Документация генерируется автоматически (Swagger на `/docs`).

| Метод и путь | Назначение | Доступ |
|---|---|---|
| `POST /auth/register` | Регистрация | Все |
| `POST /auth/login` | Вход, выдача токенов | Все |
| `POST /auth/refresh` | Обновление токенов | Все |
| `POST /auth/logout` | Выход | Авторизованные |
| `GET`, `PATCH /me` | Профиль | Авторизованные |
| `GET /tests`, `GET /tests/{id}` | Каталог и описание теста (без правильных ответов) | Авторизованные |
| `POST /attempts` | Начать попытку: весь тест или одна секция (`section_type`) | Ученик |
| `GET /attempts/{id}` | Состояние попытки и оставшееся время | Владелец |
| `POST /attempts/{id}/sections/{section_id}/start` | Начать секцию | Владелец |
| `PUT /section-attempts/{id}/answers` | Сохранить ответы Listening и Reading | Владелец |
| `PUT /section-attempts/{id}/writing/{task_id}` | Сохранить текст Writing | Владелец |
| `POST /section-attempts/{id}/speaking/{task_id}` | Загрузить аудио Speaking | Владелец |
| `POST /section-attempts/{id}/submit` | Сдать секцию | Владелец |
| `POST /attempts/{id}/abandon` | Прервать попытку | Владелец |
| `GET /attempts/{id}/result` | Результат и разбор | Владелец, преподаватель |
| `GET /me/progress` | Прогресс | Ученик |
| `GET /review/queue` | Очередь работ на проверку | Преподаватель |
| `POST /review/writing/{response_id}` | Оценить Writing | Преподаватель |
| `POST /review/speaking/{section_attempt_id}` | Оценить Speaking | Преподаватель |
| `/admin/tests/...` | CRUD тестов и их содержимого | Преподаватель, админ |
| `POST /admin/tests/{id}/publish` | Публикация теста | Админ |
| `/admin/users/...` | Управление пользователями | Админ |
| `/admin/band-conversion` | Шкалы перевода баллов | Админ |

Правильные ответы никогда не отдаются клиенту до сдачи секции.

## 5. Нефункциональные требования

### 5.1. Стек

| Компонент | Технология |
|---|---|
| Язык | Python 3.13 |
| Фреймворк | FastAPI |
| ORM и миграции | SQLAlchemy 2.0, Alembic |
| База данных | PostgreSQL 16+ |
| Файлы | S3-совместимое хранилище (MinIO) |
| Зависимости | uv (`pyproject.toml`, `uv.lock`) |
| Конфигурация | `.env` через pydantic-settings; образец в `.env.example` |
| Качество кода | ruff, pre-commit, pytest |

### 5.2. Безопасность

- Все запросы, кроме регистрации, входа и обновления токенов, требуют access token.
- Права проверяются на сервере для каждого запроса: ученик видит только свои попытки.
- Ограничение частоты запросов к `/auth/login` и `/auth/register`: не больше 10 в минуту с одного IP.
- Секреты хранятся только в `.env`, который не попадает в git.
- Загружаемые файлы проверяются по типу и размеру: аудио до 20 МБ, изображения до 5 МБ.

### 5.3. Производительность и надёжность

- Ответ API на типичные запросы — до 300 мс при 100 одновременных учениках.
- Автосохранение ответов не теряет данные при обрыве соединения.
- Время секции считается по серверным часам, а не по часам клиента.
- Ежедневное резервное копирование базы.

### 5.4. Тестирование

- Модульные тесты для проверки ответов, нормализации текста, перевода raw score в band и округления overall band.
- Интеграционные тесты API на тестовой базе PostgreSQL.
- Покрытие бизнес-логики подсчёта баллов — 100%.

## 6. Этапы разработки

| Этап | Содержание | Результат |
|---|---|---|
| 1. Основа | Модели, миграции, авторизация, профиль | Регистрация и вход работают |
| 2. Контент | CRUD тестов, загрузка файлов, публикация | Администратор может собрать полный тест |
| 3. Listening и Reading | Прохождение, таймер, автопроверка, band | Ученик проходит две секции и видит результат |
| 4. Writing и Speaking | Сдача текстов и аудио, очередь и оценка преподавателем | Полный тест с overall band |
| 5. Прогресс | Страница результата с разбором, графики прогресса | Ученик видит динамику |
| 6. AI-проверка | Предварительная оценка Writing и Speaking | Оценка без ожидания преподавателя |

## 7. Критерии приёмки

1. Ученик регистрируется, проходит полный mock-экзамен и получает overall band, совпадающий с ручным подсчётом по правилам из раздела 2.8.
2. Ученик проходит одну секцию (например, Reading) и получает band только по ней, без overall band.
3. После истечения времени секции сервер не принимает ответы.
4. Правильные ответы недоступны через API до сдачи секции.
5. Преподаватель оценивает Writing и Speaking, после чего попытка получает статус `finished`, а полный экзамен — ещё и общий балл.
6. Тест без любой из четырёх секций или без правильного ответа хотя бы на один вопрос нельзя опубликовать.
7. Все тесты из раздела 5.4 проходят, `alembic upgrade head` на чистой базе выполняется без ошибок.

## 8. Открытые вопросы

1. В README указан стек «FastAPI + Django», но проект написан на FastAPI и SQLAlchemy. Нужен ли Django (например, ради админки) или админка будет на FastAPI (например, starlette-admin)?
2. Какой AI-сервис использовать для проверки Writing и Speaking и для расшифровки аудио?
3. Будет ли платный доступ (подписка, отдельные тесты)?
4. Нужна ли связь «преподаватель — его ученики» или любой преподаватель проверяет любые работы?
